# 液态玻璃自动渲染策略（Web）

本方案遵循 `ui-ux-pro-max` Skill 的 Liquid Glass（样式 #14）和可访问性规范。用户不需要配置或选择渲染模式。

## 自动选择（按优先级）

| 运行条件 | 模式（`data-glass-engine`） | 视觉行为 |
|---|---|---|
| 支持背景模糊、SVG 与 WebGL，且未启用降低透明度／提高对比度 | `webgl` | **增强液态玻璃**：原生 CSS 背景模糊 + SVG 光学轮廓 + WebGL 折射感高光/边缘色散 |
| 支持背景模糊和 SVG，但 WebGL 不支持或 GPU 初始化/绘制失败 | `svg` | **CSS＋SVG 液态玻璃**：保留透景模糊、轮廓镜面高光，禁用 WebGL |
| 开启降低透明度或提高对比度、缺少背景模糊、SVG 不可用 | `frosted` | **CSS 毛玻璃**：更厚的半透明色层、方向性柔光和精细纹理；有背景模糊能力则继续使用模糊，设备明确要求降低透明度时不进行实时背景模糊 |

即使缺少 `backdrop-filter`，仍以纹理和柔和高光模拟**磨砂玻璃外观**，而不是未设计的不透明纯色块。但这时无法真实模糊背景图像。

## 架构

- **`glass-renderer.js`**：仅处理能力探测、模式设置、WebGL 着色器、SVG 装饰与回退；不读取、截取或重绘课程/成绩等页面内容。
- **`liquid-material.css`**：所有模式共同使用的 Liquid Glass 语义变量、毛玻璃叠层、背景模糊、暗色配对和系统可访问性回退。
- **`glass-effects.js`**：监听页面渲染完成后通知新渲染器刷新、清理过期的第三方光学实例。
- **`vendor/liquid-glass.js`**：仅在支持的非触屏小控件做有限的旧版渐进式增强，不影响新方案选择。
- **`sw.js`**：缓存上述资源供 Safari/PWA 离线访问。

## 性能与隐私

- WebGL 最多同时创建 **2 个**重点导航/选择控件的 GPU 视觉层，优先 Dock 与周／月模式。
- 单个 GL 层的像素数上限 **360,000**，设备像素比上限 **1.5**；其余元素使用 CSS＋SVG。
- WebGL 仅绘制透明光学高光与边缘色散，不创建页面截图或读取 DOM 背景纹理；真实透景模糊由浏览器原生 `backdrop-filter` 处理。因此**不是苹果系统私有的物理折射 API，也不承诺像素级背景折射**。
- GPU 上下文初始化/绘制失败时降为 `svg`；不再在页面渲染时反复分配失败的 GPU 上下文。故障时不会影响课表、成绩和按钮功能。
- 自动监听页面切换、系统深浅色、透明度/对比度偏好和屏幕尺寸变化。无需手动操作。
- 所有光学覆盖层 `pointer-events:none`，不会遮挡手势或键盘焦点。

## 回归测试

`tests/glass-renderer.test.js` 覆盖能力选择、GPU 初始化失败、系统显示偏好和毛玻璃回退；`tests/liquid-material.test.js` 验证材质与 PWA 缓存。已有导航与课程测试应持续通过。

**验收边界：** 自动化测试可验证逻辑和资源接线；真实 Safari/WebKit 对 WebGL 的 GPU 行为与光学外观仍需 iPhone 实机核验。
