# 广中医口袋 · Safari / Windows 公开部署测试版 v1.3

> **非官方、未经校方授权验证的演示／开发版。** 尚不能承诺“学生打开网页只输一次密码，就能在网站内看到真实教务与电费”。请先阅读下方的认证限制。

## 下载后先做什么？

1. Windows 安装 [Node.js LTS](https://nodejs.org/)，双击 `scripts/start-windows.bat`。
2. 本机浏览器打开 `http://127.0.0.1:4173`。运行 `npm test` 检查单元测试。
3. 要生成公开 HTTPS 地址：按照 [`docs/DEPLOY_WINDOWS_PUBLIC.md`](docs/DEPLOY_WINDOWS_PUBLIC.md)，用 GitHub Desktop 上传到自己的仓库，再在 Render 用 `render.yaml` 部署。
4. 不需要 Mac，不需要让 Windows 电脑保持开机。

## 本次增加的两项功能

### 密码暂不支持，使用微信扫码

- 登录弹窗保留「账号密码」「扫码登录」两种标签；**账号密码页明确提示“密码登录暂不支持”**，不会尝试以假表单索要学生密码。
- 「扫码登录」生成学校官方二维码。电脑上可用微信扫一扫；手机单机可先截图，再从微信「扫一扫 → 相册」识别二维码，按学校页面提示完成确认。不要共享二维码截图。
- 学校账号密码始终只在校方官网输入。仓库内保留了**默认关闭**的 CAS 回调模块供未来获校方许可后接入，不影响已验证可用的扫码登录。
- 本站的二维码同步只面向本人授权的教务课程与成绩。

### 宿舍电费查询与只读余额适配

- **实际可用入口：** 点击「宿舍电费 → 学校官网查电费」，直接在 `https://ecard.gzucm.edu.cn/user/powerfee/index` 查看自己的实时余额、绑定房间与用电明细。必要时在学校官网完成统一身份认证。
- 官网电费页面属于学校域名；Safari 无法把该域的 Cookie 交给非官方 `onrender.com` 站点，所以目前**不能承诺在广中医口袋内自动获取实时余额**。
- 本站提供「记录查询结果」功能：用户手动填写从官网查询到的电量，本地显示和趋势计算，并使用 `source:'manual'` 清晰标注。公开站点**仅此手动电量与明细**存入浏览器 localStorage；学业数据仍不持久保存。
- 代码已补全 `/user/powerfee/getBalance` 的只读查询、房间标识核验与余额数字校验。**仅在服务器已拥有合法、有效的一卡通授权会话时**才显示站内实时同步按钮。该授权目前没有自动获取路径。
- 不通过用户复制 Cookie、在本站录入学校密码或绕过学校登录来获取电费。

### iOS App → Safari 网页电量自动同步（2026-11-05）

本版本实现**设备配对、只读结果推送与浏览器历史记录**。它不是跨域复制一卡通 Cookie，也不是网页本身拥有校方 SSO 登录权限。

连接步骤：

1. 安装本项目的原生 iOS App，在电费模块内打开校方官方页面，完成一卡通登录和宿舍绑定，并读取一次真实电量。
2. 在实际部署的广中医口袋 **Web 电费页面**点击「生成设备配对码」，将**当前网页完整 HTTPS 域名**与显示的 12 位代码填入 iOS App「设置与账户 → 网站配对与电量同步」。代码五分钟有效且只能使用一次。
3. App 验证网页服务身份后，将一次性代码换成只用于推送电量的设备凭据，保存在**iOS 钥匙串**，并锁定配对的 HTTPS 站点。首次成功读取或以后 App 在前台同步电量时，会将余额、房间标签、日期、用电明细等展示字段推送到网站。
4. 网站每次进入电费页会读取关联设备数据；打开电费页期间也会定期查看是否有新记录。收到的数据会标为「iOS App 已配对推送」，刷新网页后仍保存本机历史。超过 48 小时的余额不会用于预计天数计算。

安全及限制：
- 校园卡密码、登录 Cookie、验证码、SSO Token 不会通过配对通道发送；**学校实际登录只在官方站点进行**。网页侧使用 HttpOnly 配对标识；iOS 侧仅保存绑定网站的推送凭据，不允许配对后静默切换网站地址。
- 网站 Render 免费服务通常会重启或休眠，**配对关系目前只保存在服务端内存**；重启或最长 30 天授权期限届满时需重新配对。它不是永久账户登录。
- iOS 系统不能承诺 App 关闭后保持 WebKit 活动，因此自动推送依赖 App 在前台、iOS 会话有效且学校页面仍允许查询。校方要求重新扫码、验证码或多因素认证时，必须手动完成，不会绕过。
- 用户尚未安装本项目原生 iOS App、无法配对，或服务器尚未获得校方授权时，纯 Safari 网站仍只能打开校方查询页和手动记录，**不能称为已实现独立网页版一键登录**。
- 每个网页版浏览器必须自行生成配对码完成配对；不同浏览器不会自动共享电量。请不要向陌生网站提供一次性配对码。

### 自动记录修复与限制（2026-11-05）

- 之前的缺陷：公开 Web 版使用 `store()` 不会持久化官方电量，导致一次成功查询也会在刷新或退出页面后丢失。现新增 `power-snapshots.js`，对**确实成功获取**的学校接口/官方页面余额在本机 `localStorage` 留存每天最后一次余额快照（最多保留 90 天），并保存用于预测的日用电明细。所有缓存都标为「历史缓存」，不冒充实时数据。
- 打开电费页、重新获得前台焦点、或保持该页打开时，会在有**有效的一卡通服务器端会话**的前提下按时间间隔刷新：切入页面时最短两分钟、页面保持可见时至少两小时才重复发起。浏览器关闭或后台冻结时不会承诺定时执行。
- 余额快照仅用于查询历史，不会从相邻余额的差分推断日耗（充值/更换房间会影响差值）；预计天数仍以学校每日用电明细或明确补录的数据计算。注销登录与清除本地数据会清空自动记录。
- **仍未打通的根本问题：** 当前 `EcardClient` 的服务器端 Cookie 容器没有实际授权写入来源。教务扫码或持有广中医口袋自己域名的 Cookie 不能自动登录 `ecard.gzucm.edu.cn`。普通 Safari/PWA 不可能读取另一域的 `HttpOnly` Cookie。本版本不会冒充已完成全自动一卡通同步。
- 真正的自动查询需要校方授权的一卡通 OAuth/CAS/SSO 回调与服务端会话绑定，或在用户明确安装并授予学校站点权限后由原生 iOS 应用/Safari 扩展处理授权。尚无其中任一通道时，电费页会显示明确的不可自动读取原因，保留直接访问学校官网和手动补录功能。

### 电费页面与预计可用天数（2026-11-05 更新）

- **余额来源分级**：服务端持有该用户合法的一卡通会话时，优先从校方 `getBalance` 读取，显示「官方接口实时读取」；若只能读到官网页面数值，则显示「官网页面读取（待核验）」。手动记录与 JSON 导入各有独立标签，不冒充官方实时数据。
- **跨月明细**：有授权时按需读取当前月份及上个月的每日明细、去重和日期校验；单次最多每月 3 页、每页 30 条。部分查询失败时提供提示，不把缺失值默认为 0，也不会把其他宿舍的历史记录混入。
- **预计可用天数**：`power-insights.js` 使用过去 7 个日历日内**至少 3 天**的有效每日用电记录求平均，再以当前剩余电量除以平均日耗，显示预计天数和估算耗尽日期。过期超过 48 小时的余额、最近两天没有用电记录或日均为 0 时不输出不可靠预测。
- **人工补录**：可以补录最近 90 天的某日实际耗电量。手动记录只存于本地浏览器，不与官方数据来源混淆；导入的历史数据会标记为「导入记录」。
- **刷新与缓存**：进入电费模块后，如服务器已存在该浏览器专属的一卡通授权会话，按需尝试刷新。短期重复请求最多复用 45 秒内的已验证结果；官方请求仍有速率限制，不进行高频轮询。
- **Cookie 权限边界**：广中医口袋自身的同源 Cookie 并**不等于** `ecard.gzucm.edu.cn` 的一卡通 Cookie。普通 Safari、Chrome 网页不能读取另一域名的 HttpOnly Cookie。本版本**没有新增让用户粘贴学校 Cookie 的入口**；尚未实现可稳定获得一卡通专用会话的官方回调流程。因此实际实时同步必须以后台已经拥有合法的一卡通会话为前提；否则保留学校官网直接查询与手动记账。

### App Store 风格整块按压与边缘阻尼（2026-11-05）

- 手机底部导航保留五个模块和单块连续移动的玻璃选中层，**整个按钮（图标、文字及表面）**随触摸轻微放大；手指从一个标签滑到另一个标签时，选中层随手移动，松手采用短弹簧落位。重复点击当前模块只播放短按压反馈，不重复渲染整页。
- 当手指超过最左/最右标签时，高亮位置仍被限制在导航内部，但玻璃本体会轻微横向压缩并偏移，边缘出现随超出距离增强的柔和光晕；松手后恢复原状，避免把指尖拖过末端误认为页面继续有选项。
- 普通操作按钮（查询、打开、设置、课程卡片、月份和筛选等）统一为**整个控制面缩放**，而非单独放大文字；保留键盘焦点样式、纵向滚动、移动端触摸及减少动态效果回退。
- 动效参考 iOS App Store 中系统标签栏的触感和材质分层，但普通 Safari 网页不具有 Apple 原生 Liquid Glass 交互引擎。网页用 CSS 和受控的指针手势实现相近观感。

### 统一滑动选择、液态玻璃弹窗与交互音效

- 交互弹窗（包括课程详情、扫码登录、清除数据确认、手动电量记录）会从**触发按钮所在的位置**以阻尼弹簧动画展开；关闭时缩回原触发位置。弹窗仅使用浏览器 CSS 和 Web Animations，**不是苹果 SwiftUI 原生 Liquid Glass API**。
- 顶部的「外观 / 设置」及设置页菜单同样从按钮所在点展开、反向收回；选项支持直接按住并纵向滑动选择。若菜单内容过高，优先保留自然滚动与可访问性。
- 横向分段选择控件（课表周 / 月视图、星期日到星期六、成绩类型、学分类型、登录方式），均有**共用的玻璃高亮胶囊**。手指或鼠标按住后左右滑动，高亮跟随，经过选项时放大并增强边缘高光；松手选择最近一项，普通点击也有效。
- 桌面侧栏也支持按住选项纵向拖动；手机底部导航的玻璃胶囊延续阻尼弹簧吸附。
- 本地 Web Audio API 生成很轻的短促反馈音，在滑动**跨过不同选项**时播放；不加载外部音频文件，不录音，也不发送用户数据。可以在「设置 → 玻璃交互音效」关闭；该开关本身也支持左右拖动。
- 竖向滚动不会触发横向选项切换；保留系统「减少动态效果」「减少透明度」和高对比度偏好的回退显示。紧凑月历七列直接适配手机宽度，不再需要横向滚动。
- 以上动效是参考 Safari 交互节奏的独立网页实现，并非复制苹果未公开的动画曲线或音效。

- **滑动卡顿修复：** 缓存选项几何位置，松手前同步玻璃高亮至实际指尖位置；页面重绘时从该位置继续滑向最终选项。重复选择当前选项不重新渲染整个页面，普通选项变化也不再重复播放整页入场动画。

### Safari 阻尼弹簧动画与底部手势滑动

- 底部五个模块支持 **手指横向拖动**，高亮玻璃胶囊随指尖移动；松手后自动选中最近模块，产生轻微弹簧吸附。普通点击导航仍有效，鼠标拖动也支持。
- 新的底部滑动采用近似 Safari 手感的阻尼弹簧轨迹（`safariSpringProgress`），优先用浏览器的 Web Animations API 播放分段的非线性位移动画；旧浏览器回退到 `cubic-bezier` CSS 动画。**这不是苹果未公开的 Safari 动画参数**，而是为网页自定义的物理模拟。
- 控制反弹幅度，避免夸张的果冻效果；顶部设置悬浮菜单和页面进场也使用柔和、非匀速过渡。
- 导航设置 `touch-action: pan-y`：竖向手势仍然可以滚动页面，水平方向才进入拖动；旧的课表触摸切周逻辑不会捕获底部导航手势。
- 尊重减少动态效果：仍可通过手势选择页面，但不播放弹簧位移动画；降低透明度时，玻璃高亮显示为可读的不透明选中层。

### 非线性动画与底部 Liquid Glass 选择器

- 页面进入、消息提示、按钮交互、菜单展开和课程卡片反馈统一使用 `cubic-bezier` 非线性缓动（ease-out / 轻弹簧回弹），避免匀速、机械的动画。
- 手机底部「今日 / 课表 / 成绩 / 电费 / 设置」导航增加**单块连续移动**的玻璃高亮胶囊：按下新模块后，从上一模块的位置滑动到目标位置，短暂拉伸再自然回弹；图标与文字保持清晰、可点击。
- 页面每次重绘前记录旧高亮的实际位置，以便切换模块后动画仍能连续，不会因导航 DOM 重建而闪烁重置；连续快速切换时会从当前视觉位置接续。
- 玻璃使用浏览器原生 `backdrop-filter`、边缘高光和半透明材质，不调用无法在网页内运行的苹果 SwiftUI `glassEffect`。
- 尊重系统的 `prefers-reduced-motion`、`prefers-reduced-transparency` 和高对比度设置：自动禁用移动/变形或降低透明度，保持良好可读性。

### Safari 风格悬浮选项与周/月课表

- 顶部月亮/太阳「外观」按钮与齿轮「设置」按钮会在按钮附近打开独立的毛玻璃悬浮选项框，而不是整个屏幕居中弹窗；点击空白处、滚动或按 Esc 关闭。
- 设置页面里的「外观模式」「默认启动页」「学习阶段」同样使用带圆角与选中勾号的悬浮菜单。真正的课程详情、登录授权和清除数据确认仍使用独立对话框。
- 课表增加「周视图 / 月视图」选择，默认周视图；月视图可以切换月份、按日期浏览课程、打开原有课程详情，选择会随本地外观偏好保存。
- **星期日作为日历第一天**，顺序为日、一、二、三、四、五、六。学校学期周编号继续按教务系统自身的星期一基准计算，显示前一个星期日的课程时会正确使用上一教学周的记录，不更改原始课程日期。
- 月视图在已经连接教务的前提下，仅按需读取所选月份对应的教学周；首次切换可能短暂加载，已读取的周不重复请求，不向服务器上传课表外的数据。
- **月视图采用紧凑七列日历**：每周从星期日开始，整个月均能在手机页面宽度内显示；每个日期仅展示最多两条彩色课程标记，超出的显示 `+N`，无需横向拖动。
- 点击日历中的某一天，才弹出当天所有课程的完整详情；移除原先一直展开的整月清单，减少渲染卡顿和过长页面。月度数据按需同步，打开月视图不再重复重绘一次加载状态。
- 如果某个教学周读取失败，会标明部分数据尚未获取，并提供「重试未加载课程」按钮；未完成读取时不宣称整个月数据已全部同步。

### 左侧单按钮中英切换与液态玻璃

- 顶部左侧标题旁仅保留一个 **EN / ZH** 按钮：中文界面点 EN 转英文，英文界面点 ZH 转中文；不会在「设置」里重复出现。
- 当前仍是普通 **Safari/PWA 网页**，不能调用 iOS 26 SwiftUI/UIKit 的原生 `glassEffect` 视图修饰器或原生材质 API。Safari 使用 WebKit 浏览器原生 CSS `-webkit-backdrop-filter` 配合高光、边缘与透明度效果。
- 参考并自托管 MIT 项目 [deepika-builds/liquid-glass](https://github.com/deepika-builds/liquid-glass) 的单文件光学组件，在支持的 Chromium 桌面浏览器上仅对少数导航表面增加 SVG 边缘折射；Safari/Firefox、低功耗触摸设备与降低透明度/高对比度模式仍优先清晰可读的 CSS 材质。
- 不使用第三方 CDN、远程截图或新的后台账号；课表和成绩文字仍保持可选中、可操作，不为视觉效果上传学业数据。
- 许可及归属见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

- 页面顶部左侧标题旁仅保留一个语言切换按钮：**EN**（当前中文，点击切英文）或 **ZH**（当前英文，点击切中文）。设置页不再重复提供语言选择框。
- 界面常用文字与登录、电费操作提示可在两种语言之间切换；选择保存在浏览器偏好设置中。
- 学校返回的课程名称会优先使用已经整理的英文课程名对照表；学校教务系统英文界面的**完整、准确课程译名仍需对照正式英文记录核验**，目前不声称所有课程的译名已经获得校方确认。
- 不能确认的中文课程名或其他动态中文资料在英文模式中显示 `[Translation unavailable]`，绝不使用拼音代替，也不会随意编造课程名称。切换回中文仍可看到原始官方数据。
- 学校官方英文网站可作为通用术语参照，真实课程名应以教务系统英文模式、官方英文成绩单或官方培养方案为准。
- 这不是学校官网的语言切换，学校官方认证页面仍由校方自行决定语言。

## 文件结构

- `index.html`, `app.js`, `styles.css`：iPhone / iPad / Mac / Windows 自适应界面。
- `server/server.js`：每个浏览器独立的短期会话、同源 API、安全响应头。
- `server/school.js`：官方扫码会话与本科教务数据只读查询。
- `server/ecard.js`：学校一卡通只读接口（需要有效一卡通服务器端登录态）。
- `server/parsers.js`：课表、成绩、用电页面和 JSON 解析。
- `render.yaml`：Render 自动部署。`tests/`：无需学校账号的单元测试。

## 安全须知

- 本站不能读取学校浏览器选项卡中的 `HttpOnly` Cookie；为了“方便”让学生向第三方网页交出学校密码或 Cookie 是高风险做法，不会默认实现。
- 学校官方页面的真实 URL 必须是 `https://jw.gzucm.edu.cn/`、`https://authserver.gzucm.edu.cn/` 或 `https://ecard.gzucm.edu.cn/` 等校方主机，谨防仿冒。
- Render 的免费实例可能因休眠导致登录态失效；仅用于测试，勿在获得校方授权和正式安全审计前面向全校推广。
- 本项目参考 [Hello-Minecraft/gzucm-pocket](https://github.com/Hello-Minecraft/gzucm-pocket) 的接口解析思路，保留第三方版权与 MIT 许可声明，独立非官方实现。
